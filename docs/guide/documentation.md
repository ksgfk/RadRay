# 文档维护

长期文档包含根 [AGENTS.md](../../AGENTS.md)、`docs/architecture/` 和 `docs/guide/`。
README 作为项目介绍与入口；项目技能负责维护和讨论流程。Git 保存历史版本。

| 位置 | 维护内容 |
|---|---|
| 根 AGENTS | 必须跨任务遵守的约束、按需阅读入口 |
| architecture | 当前结构、职责、接口边界、生命周期；术语和必要取舍就地解释 |
| guide | 可执行的使用、开发和验证方法 |
| architecture/overview | 全仓库地图与当前文档入口，不复制子系统细节或展开历史条目 |
| `.agents/skills/` | 本项目的 doc 与 grill 工作流程，不承载第二份技术契约 |
| `docs/history/` | 经用户授权保留的计划、开发历史、快照、实验、验收与交接；注明日期、状态和基线，不作为当前契约 |
| `docs/history/README.md` | 独立历史目录索引；可更新的导航文件，不属于冻结记录，不加日期前缀 |

先找已有页面的归属，只有出现独立、持续需要查阅的主题才新增页面。
同一个事实只维护一处，其余页面链接过去；改行为时在同一改动中更新文档。
删除文件前搜索其路径与独有术语，核对仍有效内容后归并，再修复入口和引用。

## 内容边界

`docs/architecture/`、`docs/guide/` 只记录当前代码库可核实的事实和现行开发规则：
已实现行为、接口契约、配置、已有测试覆盖与可执行操作。事实以当前声明、实现、构建配置和测试为依据；
必要的理由与代价紧邻对应实现。无法核实或已失效的说明应修正或删除，旧验收结果不作为当前保证。

这两个目录禁止保存计划、路线图、待办、提案、备选方案、实施清单、推测以及「已确认、未实现」段落。
用户确认不等于实现完成，状态标签不构成例外。当前不支持的能力可以据源码说明，不附带未来实现安排。
需要保存的计划、未实施结论、实验过程和验收记录只能按下文授权规则放入 history；未授权的内容留在会话。
外部规范只用于解释当前实现的契约，并在相关段落注明一手来源和版本；外部 checkout 不作为当前项目能力的证明。

代码注释保留调用方要求和容易误改的局部不变量。代码文件至多在文件头链接一次所属文档；
成员注释不依赖文档路径才能理解，设计说明由文档引用代码。

## 开发历史

`docs/history/` 是选择性保存的开发历史，不是每次改动都追加的 changelog。
默认不新增记录；只有用户明确要求或同意保存本次历史、过程、设计快照、实验、验收、交接时才写入。
AI 认为内容有复用或追溯价值时，可以说明拟保存的内容与理由，询问是否录入 history，不必每次改动都询问。
未回复或未明确同意时保留在会话，不阻塞其他已授权工作；已有保存授权时直接执行，不重复确认。普通实现、测试、重构、文档同步、
「带文档 grill」或历史目录整理均不自动触发新增记录。用户明确要求保存计划或未实施结论即为该记录的保存授权，无需重复询问。
当前文档仍随已实现行为变化更新，不受历史留档开关影响。

记录与附件统一命名为 `YYYY-MM-DD-主题.扩展名`，主题使用小写英文、数字和连字符，例如
`2026-10-13-material-instancing-performance.md`。CSV、JSON、图片等附件也使用日期前缀与对应主题。
日期优先采用用户指定日期或原记录明确的日期（包括原文件名中的日期）；跨日事件在正文写明范围，不因后续补测改变原记录日期。
首次归档已有材料时沿用原日期；无明确日期时使用 Git 首次保存日期，并注明来源。新记录未指定日期时使用记录当天。
附件沿用所属记录日期；同日同主题用有意义的主题后缀区分。已有记录与附件保持原样，不改名。

新增记录时注明状态、范围和基线提交，区分已实现、未采纳和待定设计，关联原始数据与所属长期页面，并核对页面头部、锚点与链接。
用户明确要求或同意保存删除或重构前的设计时，先于删除落盘，
写明依赖边界、所有权与帧生命周期；未获授权时不自动创建快照。
历史源码路径通过 `git show <基线>:<路径>` 查阅；后续源码或文档路径变化不回写历史链接与锚点。

已有 `docs/history/` 记录与附件保持原样，不修改、补注或删除。与历史相比的行为、API、约束和验证范围变化，
只在当前所属 architecture/guide 页面说明；仅保留理解现状所需的差异，必要时链接原记录。
历史数值与测试计数不迁成当前保证，未入库的本机原始数据在当前说明中注明可用性边界。
完整历史目录独立放在 [history/README.md](../history/README.md)，新增记录后维护此索引；overview 只保留入口。
索引是日期命名与历史冻结规则的唯一例外，按当前导航维护；不在索引内追加计划正文或验收日志。
目录迁移和命名整理本身不另写一篇历史。

## 页面格式

docs 页面保留简短的三行头部：

```markdown
> - 适用: 什么任务需要读本文
> - 权威: 本文负责说明哪一部分；其他部分的归属
> - 锚点: `存在的仓库相对路径`
```

根 AGENTS、README 与技能文件按各自用途组织，不套该头部。
锚点使用仓库相对路径，可用 glob；不引用个人配置文件或外部 checkout 的绝对路径。
文档链接相对当前文件书写；代码锚点相对仓库根书写。不要让文档的可用性依赖本机临时文件。
技能正文通过仓库相对路径和明确的读取说明引用文件，不使用 Markdown 文件链接、机器绝对路径或跨目录的 `../` 链接。

## 项目技能

- [radray-doc](../../.agents/skills/radray-doc/SKILL.md)：核对当前事实、整理文档与历史索引、按授权保存计划和历史。
- [radray-grill](../../.agents/skills/radray-grill/SKILL.md)：逐项追问设计；要求保存结论时使用 doc 流程。

技能随仓库维护，不要求安装用户全局技能。grill 默认在会话中讨论；确认共享理解并要求实施后
进入实现，不反复确认已经授权的事项。

## 检查

```powershell
python tools/check_docs.py
git diff --check
```

检查器覆盖 docs 目录范围和页面头部，并校验 history 文件的日期前缀与命名。
历史记录内的文档引用、源码锚点和本地链接属于记录时的基线，不按当前工作树检查其存在性。
`docs/history/README.md` 是当前索引，头部、锚点和本地链接继续严格检查，不套日期前缀规则。
当前 architecture/guide、根 AGENTS、README、项目技能和源码中的引用继续严格检查；指向 history 的链接也必须存在。
检查器不验证网页、Markdown 章节片段或语义正确性；当前文档的命令与技术事实仍须对照当前代码核查，不回写历史记录。
纯文档修改不需要构建渲染器。
