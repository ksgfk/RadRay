# 文档维护

长期文档包含根 [AGENTS.md](../../AGENTS.md)、`docs/architecture/` 和 `docs/guide/`。
README 作为项目介绍与入口；项目技能负责维护和讨论流程。Git 保存历史版本。

| 位置 | 维护内容 |
|---|---|
| 根 AGENTS | 必须跨任务遵守的约束、按需阅读入口 |
| architecture | 当前结构、职责、接口边界、生命周期；术语和必要取舍就地解释 |
| guide | 可执行的使用、开发和验证方法 |
| architecture/overview | 全仓库地图与完整文档索引，不复制子系统细节 |
| `.agents/skills/` | 本项目的 doc 与 grill 工作流程，不承载第二份技术契约 |
| `docs/history/` | 经用户授权保留的开发历史、快照、实验、验收与交接；注明日期、状态和基线，不作为当前契约 |

先找已有页面的归属，只有出现独立、持续需要查阅的主题才新增页面。
同一个事实只维护一处，其余页面链接过去；改行为时在同一改动中更新文档。
删除文件前搜索其路径与独有术语，核对仍有效内容后归并，再修复入口和引用。

## 内容边界

长期页面说明当前行为。不要把历史计划的勾选状态、旧测试计数或已被替换的设计当作当前事实。
必要的理由与代价紧邻对应规则，避免为每个小决定新建记录。

用户要求保存已确认但未实施的设计时，在所属页面加简短「已确认、未实现」段落，
写清与现状的差异。实现后更新正文并删除临时段，不在文档中维护执行日志。
未经用户授权保存的讨论、实施清单、研究过程与交接留在会话。外部事实只在相关段落引用一手来源和版本。

代码注释保留调用方要求和容易误改的局部不变量。代码文件至多在文件头链接一次所属文档；
成员注释不依赖文档路径才能理解，设计说明由文档引用代码。

## 开发历史

`docs/history/` 是选择性保存的开发历史，不是每次改动都追加的 changelog。
默认不新增记录；只有用户明确要求或同意保存本次历史、过程、设计快照、实验、验收、交接时才写入。
AI 认为内容有复用或追溯价值时，可以说明拟保存的内容与理由，询问是否录入 history，不必每次改动都询问。
未回复或未明确同意时保留在会话，不阻塞其他已授权工作；已有保存授权时直接执行，不重复确认。普通实现、测试、重构、文档同步、
「带文档 grill」或历史目录整理均不自动触发新增记录。长期文档仍随行为变化更新，不受历史留档开关影响。

文件统一命名为 `YYYY-MM-DD-主题.扩展名`，主题使用小写英文、数字和连字符，例如
`2026-10-13-material-instancing-performance.md`。CSV、JSON、图片等附件也使用日期前缀与对应主题。
日期优先采用用户指定日期或原记录明确的日期（包括原文件名中的日期）；跨日事件在正文写明范围，不因后续补测改变原记录日期。
迁移旧记录时不改为迁移当天；无明确日期时使用 Git 首次保存日期，并注明来源。新记录未指定日期时使用记录当天。
附件沿用所属记录日期；同日同主题用有意义的主题后缀区分，修改已有记录不反复改名。

每份记录注明状态、范围和基线提交，区分已实现、未采纳和待定设计；关联原始数据与当前所属长期页面。
历史文档仍遵守页面头部、锚点与链接规范。用户明确要求或同意保存删除或重构前的设计时，先于删除落盘，
写明依赖边界、所有权与帧生命周期；未获授权时不自动创建快照。
历史源码路径用行内代码保留，通过 `git show <基线>:<路径>` 查阅；头部锚点仍须存在于当前工作树。

整理已有历史时保留原始测量与基线语义，说明后续替代的 API；将仍有效的约束、理由和操作步骤迁入所属长期页面，
在历史入口链接过去。历史数值与测试计数不迁成当前保证，未入库的本机原始数据注明可用性边界。
完整入口放在 overview；目录迁移和命名整理本身不另写一篇历史。用户明确指定其他保存位置时遵循其请求。

## 页面格式

docs 页面保留简短的三行头部：

```markdown
> - 适用: 什么任务需要读本文
> - 权威: 本文负责说明哪一部分；其他部分的归属
> - 锚点: `存在的仓库相对路径`
```

根 AGENTS、README 与技能文件按各自用途组织，不套该头部。
锚点使用仓库相对路径，可用 glob；不引用个人配置文件或外部 checkout 的绝对路径。
文档链接相对当前文件书写；代码锚点相对仓库根书写。不要让文档的可用性依赖本机临时文件。

## 项目技能

- [radray-doc](../../.agents/skills/radray-doc/SKILL.md)：整理文档、同步行为、归并确认结论。
- [radray-grill](../../.agents/skills/radray-grill/SKILL.md)：逐项追问设计；要求保存结论时使用 doc 流程。

技能随仓库维护，不要求安装用户全局技能。grill 默认在会话中讨论；确认共享理解并要求实施后
进入实现，不反复确认已经授权的事项。

## 检查

```powershell
python tools/check_docs.py
git diff --check
```

检查器覆盖 docs 目录范围、页面头部与代码锚点，以及根 AGENTS、README、项目技能和源码中的
文档路径与 Markdown 文件链接，并校验 history 文件的日期前缀与命名。它验证路径存在，不验证网页、Markdown 章节片段或语义正确性；
命令与技术事实仍须对照当前代码核查。纯文档修改不需要构建渲染器。
