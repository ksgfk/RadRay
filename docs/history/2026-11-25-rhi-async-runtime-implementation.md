# RHI 并发与异步读回实施记录

对应[实施计划](2026-11-25-rhi-concurrency-and-async-runtime-plan.md)，基线为 2026-11-25 的 `65c369c1`。

- **Fence 查询目标。** `Poll()` 以本地提交快照为目标，返回实际硬件完成值。跨进程信号使用显式目标值。零时长等待返回 `NotReady`，有限等待耗尽返回 `Timeout`，设备丢失优先于缓存的完成值。同一条 timeline 的 signal 由一个队列推进，跨队列 signal 需要调用方建立执行依赖。
- **健康设备的交换链排空。** 全队列加锁后等待 idle 会阻塞尚待提交的跨队列 signal。多队列设备只等待呈现队列及未完成的 acquire fence，调用方仍须先等待旧后备缓冲的自有 GPU 工作。单队列设备保留全设备排空，将健康排空首次报告设备丢失与发布已排空状态纳入同一互斥区。
- **设备丢失的销毁顺序。** 报失路径只锁存终态。原生资源释放前执行共享排空，设备销毁在清空队列之前执行它，以便使用仍存活的队列锁。
- **窗口表面寿命。** Vulkan 交换链释放旧代及其 surface 后可用保存的窗口句柄重建。显式销毁交换链时同时清空窗口句柄，保持销毁终态。

- **上传校验的证据。** 裸映射不能证明调用方覆写了已经发布的字节。每次成功映射须对本次窗口至少 Flush 一次。在此基础上按字节保留此前已发布的数据，精确拷贝拒绝已映射而从未发布的区间。常量绑定是读取上界，纹理复制按实际块行跟踪，排除行距填充。
- **读回代次与资源寿命。** 同一队列的两笔覆写可分别发出不同 Fence。等待后一笔后再次映射曾被误报，普通读回 Buffer 在 Queue::Wait 后销毁也曾被 allocator 引用拒绝。命令现仅保留校验状态，原生提交前登记写入与信号。应用观察 Fence 时发布该队列已完成的提交序号，失败提交撤销本批，先读取旧结果时仍保留后续受门控的覆写。
- **动态源短于请求。** 构图可见 MaxSize，Prepare 才知道真实切片。Record 跳过越界请求的拷贝，让同帧其他工作完成。达到完成值后，Poll 返回失败并回收暂存和请求 ID。
- **持久映射与退役。** 所有内部读回缓冲在分配时取得映射地址。轮询和槽位退役只失效缓存并读取；采样关闭、不支持、分配失败或设备丢失都能归还成功提交的用户序号。GpuUploadBuffer 的所有权导入保活至帧回收，切片再次写入的 GPU 完成条件由宿主维护。
- **D3D12 主动诊断采集。** 双队列同时创建和释放资源时，一条队列 Wait 后的 ClearStoredMessages 会清掉另一线程刚产生的消息。活动通道按序号复制并分发可证明稳定的前缀，仅在最终释放时清空。原生报告错误、未读消息溢出和未经授权的过滤器变更仍会使测试失败。

- **跨队列的读回完成证明。** 两笔重叠写入在队列 A 完成，应用只等待下游队列 B 时，第一次失效后旧校验还留下了一笔脏记录。现在按提交序号记录各队列的等待。宿主观测下游完成值时沿围栏依赖传播，覆盖上游已完成的写入，同时保留未来的覆写。校验层只观察宿主已有的等待或查询。
- **裸导入的映射所有权。** 只经 `ImportBuffer(upload->GetBuffer(), …)` 导入时，类型化重载无法保护映射。`GpuUploadBuffer` 在既有描述符标志中携带 `OwnerMapped`，RDG 据此在构图时拒绝二次映射。原有普通 PersistentMap 缓冲仍可由调用方决定如何导入和写入。
- **取消准备的外部序号。** `BeginFrame` 后设置的序号曾跨过 `WaitIdle` 留到下一帧。未提交的槽在取消时通知流水线清理配置，下一次成功提交从 Off 和序号 0 开始。
- **有限等待的原生注册。** D3D12 的 CPU 等待超时后，先前的事件注册仍等到对应 Fence 值才结束。池项保存该值，同一事件重用前先检查完成进度，避免持续短等待累积内核注册。

- **缓存操作失败。** Vulkan 的 Flush 和 Invalidate 没有返回值。设备丢失时先锁存终态，Runtime 在读取映射地址前检查该状态，其他原生缓存错误继续按致命错误处理。

## 验证

Windows x64、MSVC Debug、NVIDIA GeForce RTX 3060。用独立构建目录分别启用和关闭 `RADRAY_ENABLE_PROFILER`。两种配置均要求 D3D12、Vulkan 可用，开启 RHI 校验和原生 GPU 辅助校验，各通过 39 个定向用例。

- **并发与 Fence。** 两条 Direct 队列各自创建资源、参数集与 PSO，共享已发布的只读参数集并执行计算。外部线程并发等待和查询 Fence，阻塞一条队列时另一条队列仍能补发信号。Vulkan probe 核对首次报失、销毁顺序与单次设备排空。
- **映射。** 非持久 Upload 映射 8192 字节，只刷新前 4096 字节，实际索引绘制得到预期像素。ReadBack 用生产者和等待线程核对字节并覆盖跨队列传递、已消费代次和未来覆写。Fake 另行验证原生提交返回前登记、失败回滚及关闭相干性检查。
- **交换链。** D3D12 覆盖 ResizeBuffers 和重新获取后备缓冲两类失败，随后在同一交换链重试并呈现。Vulkan 覆盖 Suboptimal 持帧提交、呈现与重建，以及 SurfaceLost 后重建表面并呈现。
- **Runtime。** 双后端从工作线程创建并发布的持久映射顶点和索引缓冲绘制，核对像素及通用 Buffer、Texture 读回内容。Fake 覆盖预留时映射失败、消费时零次 Map、池复用、槽位各类退役、取消准备与设备丢失后跳过时间戳读回。

完整构建使用 `cmake --build --preset win-x64-debug`。要求 D3D12、Vulkan 均可用，执行 `ctest --preset win-x64-debug --output-on-failure --timeout 150 -j 4`，共 1076 项，1072 项通过，0 项失败，4 项跳过。跳过项为 D3D12 根签名预算用例的 Vulkan 参数，以及当前适配器不支持从 Vulkan 向 D3D12 导出的 Buffer、Texture 和 Fence 三条路线。`python tools/check_docs.py` 与 `git diff --check` 均通过。
