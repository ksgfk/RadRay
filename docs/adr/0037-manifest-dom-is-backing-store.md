# ADR-0037 清单 DOM 常驻作为后备存储

状态: 生效
日期: 2026-08
影响: `modules/runtime` 的 `AssetBundleManifest` / `AssetDatabase`、`bundle.xml` 写回策略、loader 自定义子节点的消费方式、pugixml 依赖

## 背景

ADR-0036 选定 per-bundle 单一 XML 清单，动机是 git merge 冲突集中且易解。这个动机对写回
策略提出机械要求：`SaveBundle` 落盘时**不得移动未触碰的节点、不得丢弃注释**，否则一次
无关的登记操作会重排全文件，把本来平凡的 merge 变成全文冲突。同时已确认条目子节点的
**语义**完全由各资产 loader 自行解析，清单层在 Mount 时不校验它们——这意味着清单的内存
表示必须能原样保留它不理解的属性与子树。必须决定清单解析成什么、写回从什么生成，
以及 loader 以什么形态读写这些子节点。

## 决策

**`AssetBundleManifest` 不把 XML 解析成独立结构体后丢弃文档，而是把 pugixml DOM 文档本身
作为后备存储常驻内存。**

- 读取 = 在 DOM 上建索引（guid / path → 条目节点）；写回 = 序列化同一份 DOM。
  未触碰节点的顺序、内容、注释、未知属性与子树天然逐字节保持。
- 解析标志必须含 `pugi::parse_comments`——pugixml 默认丢弃注释，丢了注释的往返
  违反本决策。
- `AddEntry` 恒定把新条目追加到 `<bundle>` 末尾，不做按 path 排序插入：对既有节点
  零扰动；两个分支同时追加时的冲突是"两侧都保留"即可的平凡形态。
- loader 直接消费 `pugi::xml_node`（经 `ResolvedAsset::Node`），不经过自定义中间树。
  配套硬约束：**DOM 节点访问只允许发生在构造 `AssetLoadRequest` 的主线程时刻**；
  loader 协程一旦挂起做异步 IO 就不得再碰 DOM（`AddEntry` 可能并发修改它），
  所需参数必须在构造 task 前拷出。
- 子节点的语义归 loader，但**基础值的编码形态统一**：叶子元素的元素名是基础类型
  （`string` / `int` / `float` / `bool` / `guid`），`name` 属性是字段名，`value` 属性是值
  （如 `<int name="foo" value="1"/>`）；非叶子元素的元素名直接就是字段名（如
  `<setting>`），内部再嵌叶子或更深复合；**同名元素重复出现即列表**，不引入 `<list>`
  包装元素。清单层提供一组读写 helper（`ReadInt` / `WriteInt` 等及列表形式），loader 经
  helper 访问而不是手扒节点。**Mount 不校验子节点结构**——坏值在加载时由 loader 报错，
  子节点属于内容而非身份，整库不因单个坏值拒载。

## 放弃的方案及代价

- **解析成结构体数组、写回时全量重生成 XML**：内存表示干净、与 XML 库解耦，但重生成
  必然丢注释、丢未知属性，且任何排序/格式化选择都会移动未触碰节点，直接违反选 XML 的
  merge 动机。规范化写回想保注释就得做"增量修补 DOM"，复杂度反而高于直接常驻 DOM。
- **把 loader 子节点拷贝成自定义轻量通用树，隔离第三方类型**：换 XML 库时不用动 loader，
  但这是为大概率不会发生的迁移付税——多一套树类型、多一次深拷贝，而 pugixml 本身就是
  为嵌入设计的稳定小库。代价是 `pugi::xml_node` 出现在 `ResolvedAsset` 的公开签名里。
- **按 path 排序插入新条目**：清单文件长期保持字典序、人查起来舒服，但插入点两侧的
  上下文行成为冲突面，两个分支各插一行到相近位置就冲突；追加式把冲突压到文件末尾一处。
- **写回时统一重排 + 排序作为"规范化"**：确定性最强，但每次落盘都可能产生大范围 diff，
  与"merge 冲突集中且易解"的动机正面冲突。
- **子节点完全无编码约定，loader 各自发明形状**：清单层最薄，但每个 loader 的 XML 方言
  互不一致，读写代码无法复用，将来跨资产引用没有统一载体。选统一叶子编码后语义仍归
  loader，清单层只多了一组 helper。
- **叶子元素名当字段名（如 `<srgb value="true"/>`）**：写起来更短，但类型信息只能靠
  loader 硬记，helper 无法做类型分派；元素名=类型、`name`=字段名让读写两侧对称。
- **非叶子元素带结构类型名 + `name` 区分多实例**：清单层要理解"结构类型"概念才有意义，
  而语义解释权本来就完全在 loader；元素名即字段名与叶子规则拼起来最简单。
- **`<list>` 包装元素表达列表**：结构显式，但多一层嵌套、多一种清单层要认识的元素；
  XML 同名元素天然可重复，"重复即列表"是生态惯用形态且追加一项就是追加一行。
- **Mount 时校验子节点编码**：错误暴露更早，但子节点属于内容而非身份，整库因单个坏值
  拒载违反 ADR-0036 的错误分级；坏值推迟到加载时由 loader 报错。

## 必须保持为真

- `SaveBundle` 序列化的是 Mount/AddEntry 一路操作过的同一份 DOM 文档；不存在
  "从索引重建 XML"的代码路径。
- 解析标志含 `pugi::parse_comments`；round-trip 测试证明未触碰节点顺序、注释、
  未知属性与子树逐字节不变。
- `AddEntry` 只追加到 `<bundle>` 末尾；不存在排序插入或写回时重排。
- Mount 不校验、不重写身份契约（元素名、`guid`、`path`）之外的任何内容；子节点坏值
  由 loader 在加载时报错，不令 Mount 失败。
- 基础值只经统一编码读写：叶子元素名是五种基础类型之一、`name` 是字段名、`value` 是值；
  非叶子元素名即字段名；同名重复即列表。loader 经清单层 helper 访问，不出现第二套
  值编码或 `<list>` 包装元素。
- DOM 节点访问仅限拥有 `AssetDatabase` 的主线程，且仅限 loader task 构造完成之前；
  挂起点之后需要的数据必须已拷出。
